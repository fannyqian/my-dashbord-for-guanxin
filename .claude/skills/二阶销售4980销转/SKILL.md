# 二阶销售4980销转

用于更新二阶及线下销售的二阶升单漏斗。主指标只统计“本月新增3980/4980客户”在本月窗口内的升单；历史3980/4980客户本月升单单独展示，不并入本月新增漏斗。

## 调用方式

用户可直接使用：

```text
/二阶销售4980销转
```

默认运行当前月度窗口。若用户给出日期，转换为半开区间 `[start, end+1天)`：

```bash
python "E:/观心/数据日日/客户盘点/query_second_stage_4980_20261016.py" \
  --start 2026-10-01 \
  --end 2026-10-16
```

也可以指定 DLC 快照分区：

```bash
python "E:/观心/数据日日/客户盘点/query_second_stage_4980_20261016.py" \
  --start 2026-10-01 --end 2026-10-16 --snapshot 20261016
```

不指定 `--snapshot` 时，脚本自动查询分配、协作、订单和销售维表的共同最新分区。不要把不同快照日期静默混用。

## 日常触发约定

用户说“二阶漏斗更新”“更新二阶漏斗”或“更新二阶升单漏斗”时，自动按当前月窗口执行：

1. 探测分配表、协作表、订单明细表和销售维表的共同最新 DLC 分区；
2. 使用该快照重跑 `query_second_stage_4980_20261016.py`，窗口为当月 1 日至快照对应日期（含首尾日期）；
3. 使用最新结果刷新 `南区10月目标看板_二阶4980本地预览.html`；
4. 二阶卡片默认折叠，点击标题区域展开；支持卡片独立导出 Excel；
5. 核对3980/4980待升单客户、本月首次升单客户、升单率、升单金额、平均客单，以及历史待升单客户本月首次升单和平均升单周期；
5. 汇报快照、窗口、未匹配/重名销售、主子单异常和结果文件路径。

默认只更新本地二阶预览，不运行正式 `daily_update_10.py`，不修改 `deploy`，不提交或推送线上发布。除非用户明确要求发布，不能把本地预览结果称为线上已更新。

## 固定业务口径

- 待升单客户池：客户买过 3980/4980 入口，且入口订单之后至统计窗口开始前没有任何 `pay_amount >= 5000` 的其他实际支付订单；3980/4980入口本身不算升单。3980 与 4980 合并，按 `user_id` 去重。页面称“3980/4980待升单客户”。
- 本月新增维度：在待升单客户池中，保留窗口内 `clue_created_at` 新分配的客户；历史维度为窗口前已有入口且仍在待升单池的客户。
- 历史5000+排除看客户全部实际订单，不限制 seller_id；本月升单也看客户全部实际订单，不限制 seller_id。
- 入口金额：`actual_pay` 非空优先，否则 `pay_amount`；金额为 4980 或 3980。
- 主指标：本月新增客户数、升单客户数、升单率、升单金额、平均客单。
- 主指标升单窗口：本月统计窗口；升单订单要求有效订单状态、`pay_amount >= 1000`，且实际 `seller_id` 命中客户所属销售。
- 升单率：本月新增客户升单人数 / 本月新增3980/4980客户数。
- 平均客单：本月新增客户升单金额 / 本月新增客户升单人数；金额使用去重订单 `pay_amount` 毛额。
- 历史模块：历史3980/4980客户数、本月升单客户数、升单率、升单金额、平均客单，以及平均升单周期。
- 历史平均升单周期：每个历史客户只取本月第一笔升单，计算“首次升单支付时间 - 该客户历史入口首单支付时间”，再对本月发生升单的历史客户求平均，单位为天。
- 历史模块中的“历史4980”是历史3980/4980混合入口客户，不将3980客户冒称为纯4980客户。
- 客户按 `user_id` 去重；订单按 `user_id + order_id` 去重，父单存在时排除子单，缺主单组合写入审计。
- 转化业绩严格按订单实际售卖人 `seller_id` 归属，使用 `pay_amount` 毛额；退款金额单列。
- 合并漏斗：历史与本月新增统一展示；合计客户、升单客户、订单和金额必须按 `user_id` 与 canonical `order_id` 全局去重，不能直接相加历史和本月两队列。
- 组织到人：统一按 `归属（二阶/线下）→组别（观鼎组/院区）→销售人员（销售ID）` 展示历史、本月新增、合计三组指标。
- 页面沿用398卡片逻辑：六张合计指标卡、两阶段合并漏斗、历史/本月拆分说明；组织、组别/院区、销售人员表通过“合计/历史/本月新增”切换查看，列为队列、升单、升单率、升单金额、ARPU。
- 协作记录保留审计但不增加主客户数；订单金额只按实际 `seller_id` 归属，不按协作销售拆分。

## 输出

结果写入 `E:/观心/数据日日/客户盘点/second_stage_4980_<起始日期>_<结束日>/`：

- `销售汇总.csv`：每名销售的新增/历史客户数、转化人数、转化订单、支付业绩和退款。
- `客户明细.csv`：匿名 `user_id` 级队列、入口、分配和转化明细。
- `订单审计明细.csv`：窗口订单、金额、seller/assistant、主子单和冲突字段。
- `查询审计.json`：快照、销售匹配、客户去重、主子单排除和异常信息。

不导出客户姓名、手机号或昵称；不覆盖原始 Excel、模板或旧结果。

## 执行后汇报

汇报时必须说明：统计窗口、DLC 快照、本月新增3980/4980客户数、升单客户数、升单率、升单金额、平均客单；历史3980/4980客户数、本月升单客户数、升单率、升单金额、平均客单、平均升单周期；未匹配/重名销售及主子单异常。若查询失败、权限不足或快照无法覆盖窗口，不能填假 0。

## 验证

检查 `销售汇总.csv` 与客户/订单明细二次聚合一致；确认日期边界为含首尾日期、`seller_id` 命中、转化人数不超过客户数，并报告销售间客户重叠及缺失主单异常。

## 安全与凭据

脚本沿用客户盘点 `_run_roster_query.py` 的运行时凭据读取和查询缓存，不在 Skill、脚本输出或报告中写入 DLC 密钥。查询为只读，不发送外部消息，不修改模板。
